# Задача: сцена NPC «Коллекция» (фронтенд)

## Контекст

Проект — фронтенд браузерной игры «Тюряга». Уже есть двор с кнопками
(например, «игра в карты»). По нажатию на такую кнопку открывается
сцена

Бэкенд уже отдаёт всё нужное. **Ничего на бэке не менять.** Работаем только
с существующими ручками. Все запросы — через `fetch` с `credentials: 'include'`
(сессия cookie, прокси уже настроен — домен указывать не нужно, пути относительные).

## Что делаем

Добавить во двор **кнопку «Коллекция»** (или «NPC», «Скупщик» — стиль как у
кнопки игры в карты). По нажатию открывается **сцена работы с коллекционными
предметами**:

- видны все предметы персонажа (что у него есть),
- видны все предметы каталога (в том числе которых у него нет),
- можно переключать фильтры «Мои / Все»,
- видно сколько у игрока **молотков** (`hammers`),
- у каждого предмета видна **редкость** — цветной каймой/обводкой (см. таблицу цветов),
- можно **выбрать любой предмет и перероллить ему редкость за молоток**,
- если у предмета есть `pendingRarity` — показать предложение **апгрейда за сигареты**
  и кнопку «Улучшить».

## API — что есть на бэке

Все ручки защищены сессией: без логина `401 { error: "Not authenticated" }`.
Ошибки: `400 { error: "..." }` (бизнес-правило), `500 { error: "..." }`.

### `GET /api/npc/collection`

Вся коллекция игрока + полный каталог предметов + суммарный бонус.

**Ответ** (реальный, уже проверен):

```json
{
  "items": [
    {
      "itemId": "bone_shiv",
      "name": "Костяная заточка",
      "icon": "/img/collection/bone_shiv.png",
      "statType": "dmg_knife",
      "purchasable": false,
      "rarity": "blue",
      "rarityName": "Синяя",
      "pendingRarity": null,
      "pendingRarityName": null,
      "currentStat": 17,
      "pendingStat": null
    }
  ],
  "catalog": [
    {
      "itemId": "bone_shiv",
      "name": "Костяная заточка",
      "icon": "/img/collection/bone_shiv.png",
      "statType": "dmg_knife",
      "baseStat": 15,
      "maxStat": 23,
      "purchasable": false,
      "price": null,
      "dropSources": [
        { "bossId": 1, "bossName": "Кисель", "chance": 30 }
      ],
      "owned": true,
      "rarity": "blue",
      "rarityName": "Синяя",
      "currentStat": 17,
      "pendingRarity": null,
      "pendingRarityName": null,
      "pendingStat": null
    }
  ],
  "bonus": { "dmg_knife": 17, "dmg_pistol": 0, "dmg_poison": 50 }
}
```

- `items` — только то, что у игрока **есть** (для фильтра «Мои»).
- `catalog` — **все** предметы каталога (для фильтра «Все»). У невыпавших
  `owned: false`, `rarity: null`, `currentStat: null`.
- `dropSources` — с каких боссов падает предмет и с каким шансом (для карточки).
- `bonus` — суммарный бонус к урону по типам (показать сверху сцены).
- `baseStat` — «белая» база, `maxStat` — стат на легендарке (для превью диапазона).
- `pendingRarity != null` → у предмета есть доступный апгрейд за сигареты.

### `GET /api/npc/collection/upgrades`

Список предметов с `pendingRarity != null`.

```json
[
  {
    "itemId": "bone_shiv",
    "name": "Костяная заточка",
    "icon": "/img/collection/bone_shiv.png",
    "statType": "dmg_knife",
    "fromRarity": "white",
    "toRarity": "blue",
    "fromStat": 15,
    "toStat": 17,
    "price": 1000
  }
]
```

### `POST /api/npc/collection/upgrade`

Тело: `{ "itemId": "bone_shiv" }`. Списывает сигареты, применяет `pendingRarity`.

**Успех:**
```json
{ "ok": true, "cigarettes": 4000, "item": { ...обновлённый предмет... } }
```

Ошибки:
- `400 "Не хватает сигарет"` — если сигарет меньше `price`.
- `400 "Нет доступного улучшения"` — если `pendingRarity` уже `null`.
- `400 "Предмета нет в коллекции"` — если предмета нет.

### `POST /api/npc/collection/reroll`

Тело: `{ "itemId": "bone_shiv" }`. Списывает **1 молоток** (`hammers`),
переролливает редкость. **Редкость никогда не понижается.**

**Успех:**
```json
{
  "ok": true,
  "rarity": "blue",
  "rolled": "green",
  "upgraded": true,
  "hammers": 4,
  "item": { ...обновлённый предмет... }
}
```

- `rarity` — итоговая редкость (после переролла).
- `rolled` — что выпало (для показа «выпало: зелёная»).
- `upgraded: true` — редкость повысилась; `false` — выпало хуже/равно, редкость
  осталась прежней (молоток всё равно потрачен).

Ошибки:
- `400 "Не хватает молотков"` — если `hammers < 1`.

### `GET /api/npc/shop` и `POST /api/npc/shop/buy`

Витрина покупных предметов и покупка. Формат — как у `catalog` с `purchasable: true`.
Покупка: тело `{ "itemId": "brass_knuckles" }`, успех → `{ success: true, cigarettes, item }`.
**В рамках этой задачи магазин можно не рисовать** (отдельная итерация), но
если хочется — сделай вкладку «Магазин» в той же сцене.

### Где взять `hammers` и `cigarettes`

`GET /api/me` → поле `hammers` и `cigarettes`. Показывать в шапке сцены.

## Цвета редкостей

Обводка карточки предмета — по `rarity`:

| `rarity` | Название | Цвет |
| --- | --- | --- |
| `white` | Белая | `#cccccc` |
| `blue` | Синяя | `#4a90d9` |
| `green` | Зелёная | `#4caf50` |
| `purple` | Фиолетовая | `#9c27b0` |
| `legendary` | Легендарная | `#ff9800` (золотая) |

Для невыпавших (`owned: false`) — серая рамка `#444` и полупрозрачная карточка.

## UI — что должно быть на сцене

### Шапка
- Заголовок «Коллекция» (или «Скупщик», «NPC»).
- Кнопка закрытия «×» (возврат во двор).
- Бейджи: `Сигареты: <cigarettes>`, `Молотки: <hammers>`.
- Суммарный бонус: `Урон: нож +17, пистолет +0, яд +50` (из `bonus`).

### Фильтры (табы/кнопки)
- **«Мои»** — только `items` (то, что у игрока есть).
- **«Все»** — весь `catalog`.
- **«Апгрейды»** — только те, у кого `pendingRarity != null` (по сути `GET /api/npc/collection/upgrades`,
  но можно фильтровать `catalog` на клиенте).
- **«Магазин»** (опционально) — `GET /api/npc/shop`.

### Сетка карточек

Каждая карточка — квадрат с:
- иконкой предмета (`icon`),
- названием (`name`),
- обводкой цвета редкости (см. таблицу),
- статом: `+<currentStat> к <statType>` (для owned) или `?` (для не owned),
- маленьким бейджем с названием редкости (`rarityName`),
- индикатором, если есть `pendingRarity` (например, стрелка вверх или значок «↑»).

Для `owned: false` — карточка приглушена, вместо стата `?`, показать `dropSources`
(«Падает: Кисель 30%»), кнопок действий нет.

### Действия по клику на карточку

Открывается панель/тултип с деталями:

- Иконка, название, редкость.
- `currentStat` → `+17 к dmg_knife` (расшифровать `statType`:
  `dmg_knife → «урон ножом»`, `dmg_pistol → «урон из пистолета»`,
  `dmg_poison → «урон ядом»`).
- Если `pendingRarity != null`:
  - «Доступно улучшение: `rarityName` → `pendingRarityName` (`currentStat` → `pendingStat`)».
  - Кнопка **«Улучшить за N сигарет»** (N — из `GET /api/npc/collection/upgrades`
    или запросить `price` отдельно; проще — из `upgrades`, но можно захардкодить
    запрос `upgrades` при открытии деталей).
  - При клике → `POST /api/npc/collection/upgrade`. При успехе — обновить карточку,
    обновить бейдж сигарет.
- Кнопка **«Перероллить за 1 молоток»** — всегда (для owned).
  - При клике → `POST /api/npc/collection/reroll`.
  - При успехе — показать анимацию/сообщение:
    - `upgraded: true` → «Выпало: `rolled` → теперь `rarity`».
    - `upgraded: false` → «Выпало: `rolled` — хуже, оставили `rarity`».
  - Обновить карточку и бейдж молотков.
- Кнопка «Закрыть».

### Пустые состояния

- Коллекция пуста (в `items` пусто) → «У тебя пока нет предметов. Выбей их с боссов».
- Апгрейдов нет → «Нет доступных улучшений. Выбей предмет лучшей редкости».
- Молотков 0 → кнопка «Перероллить» disabled с подсказкой «Нужен молоток».

## Порядок внедрения

1. Кнопка «Коллекция» во дворе (стиль как у «Игра в карты»).
2. Модалка/сцена: шапка с бейджами (`cigarettes`, `hammers`, `bonus`), кнопка закрытия.
3. `GET /api/npc/collection` → сетка карточек с обводкой по редкости.
4. Фильтры «Мои / Все / Апгрейды».
5. Клик на карточку → панель деталей.
6. Кнопка «Перероллить» → `POST /api/npc/collection/reroll` + обновление.
7. Кнопка «Улучшить» (если `pendingRarity`) → `POST /api/npc/collection/upgrade`
   + обновление.
8. Пустые состояния и disabled-кнопки.

## Что НЕ делать

- **Не менять бэкенд.** Все ручки уже готовы.
- **Не дублировать `hammers`** — брать из `GET /api/me`, не считать на клиенте
  «сколько было минус сколько потратил» (параллельные запросы собьют).
- **Не хранить коллекцию в localStorage** — источник правды только бэкенд.
- **Не выдумывать редкости** — только `white / blue / green / purple / legendary`
  и цвета из таблицы.
- **Не понижать редкость на клиенте** — переролл не понижает, если бэк вернул
  `upgraded: false`, редкость осталась прежней; показать сообщение, не менять карточку.
- **Не отправлять запросы без `credentials: 'include'`** — иначе `401`.
- **Не рисовать магазин в этой итерации**, если не просили — отдельная задача.

## Грабли

- **Гонки.** Если игрок дважды быстро нажал «Перероллить», второй запрос может
  уйти до обновления `hammers` в стейте. Делай **оптимистичный лок** (disable кнопку
  до ответа) — иначе можно потратить больше молотков, чем кажется.
- **`upgraded: false`** — это не ошибка. Молоток потрачен, редкость прежняя.
  Показать сообщение, обновить `hammers` из ответа.
- **`pendingRarity`** — показывать как «доступен апгрейд», но **не менять**
  `currentStat` в карточке, пока игрок не оплатил. `currentStat` = то, что
  реально бафает урон; `pendingStat` — превью.
- **`owned: false`** — не показывать кнопки «Перероллить» / «Улучшить».
- **`401`** — если сессия протухла, показать «Войдите заново» и редирект на логин.
